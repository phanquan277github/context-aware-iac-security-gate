# Dataset Source & Provenance Policy

## Purpose

This document defines the source-selection and provenance
rules for the Main Dataset.

Public datasets and repositories are treated as seed/source
material only. They are not treated as the ground truth for
security-priority ranking.

All retained Terraform configurations are revalidated locally
and rescanned using the frozen Checkov 3.3.17 version.

## Source Roles

### Security Pattern Source

Used to obtain known security-misconfiguration patterns.

### Task Diversity Source

Used to increase Terraform/AWS code and task diversity.

### Security Benchmark Reference

Used as a reference for security controls and candidate cases.

### AI-Generated Terraform Source

Used to obtain Terraform artifacts generated by generative AI.

The main dataset must contain AI-generated Terraform artifacts.

## Seed Admission Criteria

### MUST

- AWS
- Terraform
- Self-contained and reproducible
- terraform validate passes
- Checkov 3.3.17 runs successfully
- At least one in-scope finding
- Provenance is identifiable
- License/provenance is sufficiently verified for use
- No real AWS deployment required for reproduction

### PREFERRED

- At least 3 in-scope findings
- Approximately 4–6 in-scope findings is preferred
- Suitable for contrastive context construction
- Not duplicated by another seed

### AVOID

- Excessive module complexity
- Difficult external dependencies
- Dynamic or time-dependent behavior
- Duplicate scenarios

## Finding Retention

Raw scanner findings must not be truncated to force a preferred
number of findings per seed.

Seeds that are unsuitable because of excessive or problematic
findings should be rejected rather than truncated.

## Provenance Requirements

Each retained seed must record:

- seed_id
- source_id
- source_name
- source_reference
- source_version
- source_commit
- license
- license_verified
- cloud
- IaC format
- original path
- local path
- modifications
- admission status

For AI-generated artifacts, record when available:

- model
- model version
- prompt or task identifier
- generation parameters
- generation date
- original artifact identifier

Unknown values must be recorded as unknown rather than inferred.

## Version Pinning

The exact source version or commit used for each retained seed
must be recorded.

Current repository state must not be used as an implicit version.

## Scanner Reproduction

Public scanner results are reference material only.

The project retains its own local validation and Checkov 3.3.17
outputs for every admitted seed.

## Ground Truth Separation

Public labels, benchmark labels, model rankings, or other external
judgments must not be copied as the thesis ground-truth ranking.

Ground truth is created separately by the project's annotation
procedure.

## Freeze

The source-selection policy and provenance schema are frozen
before Main Seed Acquisition.

Actual seed-level admission and exact source commits are recorded
during STEP 10.
